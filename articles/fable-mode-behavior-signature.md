Claude Codeの最上位モデル Claude Fable 5 には週間利用上限があります。上限を使い切ったあと、下位モデルに切り替えた瞬間に感じる「仕事の進め方が違う」という感覚。あの差の正体は何なのか。モデルの賢さそのものは移植できませんが、**観測できる働き方**なら移植できるのではないか — というのがこのプロジェクトの出発点です。

作ったものはこちらです。

https://github.com/okazaky/fable-mode

## やったこと: 蒸留ではなく「行動署名」の抽出

まず前提として、モデルの出力を使った学習・蒸留は利用規約で禁止されています。このスキルがやっているのはそれではありません。

自分自身のClaude Codeセッションログ（Fable 5が動いた**406セッション・24,896ターン**）をローカルにアーカイブし、そこから「このモデルは仕事をどう進めているか」という**行動パターンだけ**を抽出しました。重みでも能力でもなく、働き方の癖。これを「行動署名（behavior signature）」と呼んでいます。

抽出は3段階で行いました。

1. **全ログの横断分析**: ツール呼び出しの前後で何を言うか、エラー時にどう報告するか、破壊的操作の前に何をするか、をセッション横断で集計
2. **原則への圧縮**: 繰り返し観測されたパターンを12の作業原則に言語化
3. **本人によるセルフ監査**: 抽出した原則をFable 5自身に見せ、新しいログサンプルと突き合わせて「これは自分の行動と一致するか」を検証させる — この工程で2つの原則が修正されました

## 抽出された12原則（要約）

| # | 原則 |
|---|---|
| 1 | 即実行・前置きは1文まで。ツールだけのターンは正常 |
| 2 | 作る前に既存を読む（メモリ・既存ファイル・過去ログ） |
| 3 | 集計やダッシュボードを信用せず生データまで掘る |
| 4 | 破壊的・外部向け操作の前に安全ゲート（バックアップ・事前承認） |
| 5 | 「完成」と言う前に実物で検証（curlでステータス確認・実レンダラで開く） |
| 6 | 長い処理はバックグラウンド化し、再開手順を先に宣言する |
| 7 | 正直な構造化報告: 完了（証拠つき）/未完了/次の一手 |
| 8 | 本筋と副産物を分離し、判断点は1〜2個に絞って提示 |
| 9 | プロジェクトの掟への準拠 — ただし**フック環境込みで** |
| 10 | 質問は必ず1問ずつ、選択肢＋推奨マーク付き |
| 11 | 完了報告と一緒に「次を安くする道具」を残す |
| 12 | 自分の成果物を正直に評価する（弱ければ弱いと言う） |

## いちばん面白かった発見: 原則9

セルフ監査で判明したのですが、ログ上で観測された「掟への高い準拠率」は、モデル単体の性質ではありませんでした。**モデル＋フック環境（完成宣言ゲート・教訓の自動注入）の合成物**だったのです。

つまりこのスキルをプロンプトとして貼るだけでは、あの準拠率は再現しません。同等のフックを併設して初めて近づく — この事実はSKILL.md本文に正直に書いてあります。「プロンプトだけで人格が移る」という幻想を売らないことが、この手のプロジェクトの誠実さだと考えています。

## アーカイブの扱い（セキュリティ）

生のセッションログには、認証情報や個人情報が本質的に含まれます。リポジトリで推奨している運用は次のとおりです。

- アーカイブはローカル限定。ディレクトリ `0700`・ファイル `0600`
- 抽出やセルフ監査でクラウドモデルに渡すのは**リダクション済みのQ&Aエクスポート**のみ。生ログ投入は「明示的に承認した意図的な1ステップ」としてのみ行う
- 保持期間を決め、期限切れの生ログは確実に削除する

なお、この記事のリポジトリ自体も、公開前にClaude Fable 5とOpenAI Codexの**別系統2モデルによる敵対的セキュリティ監査**を通してから公開しています（監査で13件刺されて全修正した顛末は、model-routerの記事で詳しく書きます）。

## 使い方

```bash
git clone https://github.com/okazaky/fable-mode
cp -r fable-mode ~/.claude/skills/fable-mode
```

Claude Codeで「fable mode」「work like Fable」と言えば発動します。`output-styles/fable-like.md` を出力スタイルとして常用する運用も可能です。

## 正直な限界

- これはプロンプトレベルの作業規律であって、モデルではありません。**能力は1ミリも移りません**
- 移るのは「進め方」だけです。ただ実務では、能力差より進め方の差が成果を分ける場面が意外に多い、というのが406セッションを見返した実感です
