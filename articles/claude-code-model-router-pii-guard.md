Claude Codeを本気で使い込むと、モデルは1つでは足りなくなります。最上位モデルには週間上限があり、簡単な仕事に使うのはもったいない。かといって全部を下位モデルに振ると、判断を誤ったときの手戻りが高くつく。さらに外部CLI（Codexなど）や、データの行き先に気を使うべきプロバイダも混ざってくる。

この「どの仕事をどのモデルに振るか」を1年運用して固まった設計をOSSにしました。

https://github.com/okazaky/claude-code-model-router

## 設計思想は3つ

### 1. 「振り分けない」がデフォルトの3層ルーティング

- **間違えると高くつく判断**（設計・根本原因診断・一回性の意思決定）→ 最上位モデル
- **通常の実装** → 中位モデル
- **機械的な物量仕事**（grep集計・定型変換）→ 下位モデル
- **セカンドオピニオン** → 別系統のモデル（例: Codex）。実装者と同じ盲点を共有しないため

重要なのは、委譲には実コストがある点です。手順書を書き、コンテキストを渡し、結果を検証する — この往復より利得が明確に大きいときだけ振り分けます。迷ったらメインループが自分でやる。ルーティング表はYAMLに外出しし、スキル本文は表を実行するだけの構造です。

### 2. fail-closed のPII/シークレットガード

データ所在に気を使うべきプロバイダへテキストを送る前に、必ずスキャナを通します。

```bash
python3 scripts/pii_guard.py prompt.txt     # exit 0 = 通過 / exit 2 = 送信禁止
```

検出対象は、ベンダー固有のシークレット約40種・汎用的な認証情報代入・JWT/秘密鍵ブロック・高エントロピー文字列・Luhn検証つきカード番号・日本のPII（電話/口座/マイナンバー形式）・そして**ローカル禁止語リスト**（自分の名前・住所・案件コードネーム）。1件ヒットで送信禁止です。

「fail-closed」の意味はここにあります。

- 禁止語リストが未設定なら**スキャン自体をブロック**（設定漏れのまま素通りさせない）
- UTF-16などデコード不能な入力も**ブロック**(「読めなかったので通す」を許さない)

### 3. 実装者に「できました」を言わせない独立検証プロトコル

委譲先の完了報告は主張であって事実ではありません。**実装したモデルとは別系統**の検証者（別ベンダーのレビューCLI、または上位モデル）が、生成物を実際に開き、コードを実際に動かして確認してから完了宣言する。これをプロトコルとして固定しています。

## 公開前に自分自身が監査対象になった話

このリポジトリ、公開前にCodexによる敵対的監査を通したところ**13件の指摘**が出ました。セキュリティツールを名乗る側が刺される、いちばん教育的な展開です。代表例を晒します。

- **シェルコマンドインジェクション**: プロンプト文字列を `"<prompt>"` とシェルに直接テンプレート展開していた。プロンプト内の `$()` やバッククォートがCLI到達前にシェルで評価される。修正後は必ずファイル経由:

```bash
PROMPT_FILE=$(mktemp)
cat > "$PROMPT_FILE" <<'PROMPT'
...prompt text...
PROMPT
codex exec --skip-git-repo-check "$(cat "$PROMPT_FILE")"
```

- **UTF-16バイパス**: UTF-16でエンコードした入力が全パターンをすり抜けていた → デコード不能入力は一律ブロックに変更
- **禁止語リストのfail-open**: リスト未設定時に「個人情報の定義が空のまま」スキャンが通っていた → 未設定はブロックに変更
- 40文字AWS型シークレットの `/` 含みが未検出、Mastercard 2xxx系と19桁PANが未対応、メール正規表現の多項式バックトラッキング（ReDoS）… など

全件修正後の再監査でクリアし、self-testは56/56通過。**修正済み項目と、直せない固有の限界（ラベルなし12桁数字は検出不能・多段難読化は素通り）の両方をREADMEに明記**しています。「このスキャナだけに頼るな」と自分で書いてあるスキャナです。

## おまけ: GitHubに公開をブロックされた

pushしたら `GH013: Repository rule violations` で拒否されました。犯人はself-test内のダミーGitLabトークン。**スキャナのテストフィクスチャが本物のシークレットと判定された**わけです。

対処は例外URLでの許可ではなく、フィクスチャの実行時連結への書き換えにしました。

```python
("glpat-" + "aB3dE5fG7hJ9kL1mN3pQ", True, "GitLab token"),
```

ソース上に連続したシークレット形状のリテラルが存在しなければpush protectionは反応せず、テスト実行時には結合済み文字列がスキャナに渡るので検出テストとしては同一です。例外化を選ばなかったのは、フォークした人が全員同じブロックを踏むからです。
